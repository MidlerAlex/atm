# Как понимать, какие слова вытаскивать из задачи для поиска

Когда ты знаешь только **что нужно сделать**, но не знаешь название механизма, твоя первая задача — не угадать технический термин.

Нужно сначала вытащить из задачи **смысловые слова**, а уже потом через поиск прийти к словам вроде:

- `unique`
- `constraint`
- `transaction`
- `select_related`
- `F expression`
- `idempotency`

То есть правильный путь такой:

```text
Задача человеческими словами
        ↓
Вытащить смысл
        ↓
Сделать первый простой поиск
        ↓
Увидеть технический термин
        ↓
Искать уже по нему
        ↓
Документация
```

---

# Главное правило

Тебе **не нужно заранее знать слово `unique`**.

Например ты думаешь:

> Я хочу запретить создавать две записи с одинаковым значением поля.

Ты можешь вообще не знать, что это называется `uniqueness`.

Это нормально.

Твоя задача сначала получить что-то вроде:

```text
django
model
prevent
duplicate
field value
```

И уже в результатах поиска ты можешь впервые встретить:

```text
unique
unique constraint
```

После этого появляется новый, более точный запрос.

---

# Шаг 1. Возьми задачу как есть

Например:

> Я хочу запретить создавать два объекта с одинаковым значением поля.

Не пытайся пока сделать из этого технический запрос.

---

# Шаг 2. Убери всё, без чего смысл не меняется

Исходная фраза:

```text
Я хочу запретить создавать два объекта с одинаковым значением поля
```

Убираем:

```text
я хочу
создавать
два объекта
с
```

Остаётся смысл:

```text
запретить
одинаковое значение
поле
```

Добавляем область:

```text
Django model
```

Получаем основу для поиска:

```text
django model prevent duplicate field value
```

---

# Шаг 3. Используй четыре вопроса

Когда не понимаешь, какие слова брать, прогоняй задачу через эти вопросы:

```text
1. С чем я работаю?
2. Что я хочу сделать?
3. Какое условие или ограничение важно?
4. Где это происходит?
```

---

## Пример 1. Запретить дубликаты

Задача:

> Нельзя создать две записи с одинаковой subscription.

Разбираем:

```text
С чем?
subscription / field

Что хочу?
запретить повтор

Какое ограничение?
значение не должно повторяться

Где?
Django model / database
```

Первый поиск:

```text
django model prevent duplicate field
```

или:

```text
django field value cannot repeat
```

После этого ты можешь встретить:

```text
unique
uniqueness
UniqueConstraint
```

И только тогда перейти к:

```text
django unique constraint
```

---

# Шаг 4. Формулируй не только действие, но и правило

Иногда искать легче не через:

```text
Что должен сделать код?
```

а через:

```text
Какое правило должно соблюдаться?
```

Например:

> Запретить две одинаковые записи.

Можно переформулировать:

> Значение не должно повторяться.

Или:

> Значение должно быть уникальным.

Даже если слово `unique` ты не знаешь, можно искать:

```text
django field value cannot repeat
```

или:

```text
django no duplicate field values
```

---

# Шаг 5. Ищи свойство, которое решает проблему

Очень полезный приём:

```text
ПРОБЛЕМА
↓
Какое СВОЙСТВО системы решило бы её?
↓
ищу название свойства
```

Примеры:

```text
"не должно быть дубликатов"
→ uniqueness

"несколько операций не должны выполниться наполовину"
→ atomicity

"повторный вызов не должен создать дубль"
→ idempotency

"не хочу много запросов к БД"
→ eager loading / select_related

"обновление не должно потеряться при конкуренции"
→ atomic update / F expression

"если объекта нет — создать"
→ get_or_create
```

Ты не обязан знать эти слова заранее.

Они появляются постепенно по мере практики.

---

# Шаг 6. Оставляй слова, без которых задача меняет смысл

Хороший способ понять, важное слово или нет:

> Удали слово и посмотри, изменилась ли задача.

Например:

> Запретить две записи с одинаковым email.

Если убрать `email`:

> Запретить две записи с одинаковым значением.

Суть почти не изменилась.

Значит `email` — не главное слово для поиска.

Если убрать:

```text
одинаковым
```

получится:

> Запретить две записи.

Это уже другая задача.

Значит:

```text
same
duplicate
repeat
unique
```

— слова, связанные с сутью задачи.

---

# Шаг 7. Не пытайся сразу писать идеальный английский запрос

Например:

```text
django orm forbid create two objects with equal field value
```

человеку понятен.

Но документация, скорее всего, использует не:

```text
forbid create two objects
```

а:

```text
duplicate
unique
constraint
field
```

Поэтому лучше делать несколько коротких запросов:

```text
django duplicate field
```

потом:

```text
django unique field
```

потом:

```text
django unique constraint
```

---

# Поиск — это цепочка, а не один запрос

Нормальный путь новичка:

```text
"не должно быть двух одинаковых записей"

↓

django prevent duplicate field value

↓

в результатах встречаю:
unique

↓

django unique field

↓

понимаю, что нужен условный случай

↓

django unique with condition

↓

UniqueConstraint(condition=...)

↓

официальная документация
```

То есть ты не обязан попасть в документацию с первой попытки.

# Ещё примеры

## Пример 2. Много запросов к БД

Задача:

> Я получаю Subscription, потом обращаюсь к Product и User, и Django делает много запросов.

Разбор:

```text
С чем?
Subscription + Product + User

Что?
получить связанные данные

Ограничение?
не делать много запросов

Где?
Django ORM
```

Первый поиск:

```text
django foreign key avoid multiple queries
```

или:

```text
django load related objects one query
```

Находишь:

```text
select_related
```

---

## Пример 3. Откат при ошибке

Задача:

> Если одна операция записи в БД упала, предыдущие тоже должны отмениться.

Разбор:

```text
С чем?
database changes

Что?
отменить

Когда?
при ошибке

Где?
Django database
```

Первый поиск:

```text
django rollback database changes on error
```

Находишь:

```text
transaction
atomic
```

---

## Пример 4. Увеличить поле безопасно

Задача:

> Хочу увеличить счётчик на 1, но два процесса могут обновить его одновременно.

Разбор:

```text
С чем?
database field / counter

Что?
increment

Ограничение?
concurrent update / race condition

Где?
Django ORM
```

Первый поиск:

```text
django increment database field safely
```

или:

```text
django update field without race condition
```

Находишь:

```text
F expression
```

---

## Пример 5. Получить или создать

Задача:

> Если объект есть — получить, если нет — создать.

Разбор:

```text
С чем?
object

Что?
get or create

Условие?
если не существует

Где?
Django ORM
```

Запрос:

```text
django get object if exists otherwise create
```

Находишь:

```text
get_or_create()
```

# Как понять, что слово хорошее для поиска

Хорошее поисковое слово обычно относится к одному из этих типов:

```text
Объект:
model
field
queryset
foreign key
database
request
response

Действие:
create
update
compare
filter
rollback
increment
load

Проблема:
duplicate
race condition
multiple queries
error
missing object

Ограничение:
unique
conditional
atomic
active
pending
one query
```

Не обязательно иметь по одному слову из каждой группы.

Главное — собрать 2–5 слов, которые описывают суть.

---

# Мини-шаблон для поиска

Когда застрял, заполни:

```text
Я работаю с:
...

Я хочу:
...

Проблема / ограничение:
...

Где:
...
```

Потом преврати это в короткий запрос:

```text
<technology> + <action/problem> + <object>
```

Например:

```text
django + prevent duplicate + field
```

---

# Когда техническое слово уже найдено

Как только ты встретил термин вроде:

```text
UniqueConstraint
select_related
transaction.atomic
F expression
get_or_create
```

перестаёшь искать проблему человеческими словами.

Теперь ищешь сам термин:

```text
django UniqueConstraint
```

или:

```text
site:docs.djangoproject.com UniqueConstraint
```

# Когда спрашивать ChatGPT

Если после 10–15 минут ты всё ещё не можешь понять, как вообще называется нужный механизм, хороший запрос такой:

> Мне нужно сделать X. Не пиши готовое решение. Помоги перевести мою задачу в технические термины и скажи, что искать в документации.

Например:

> Мне нужно не допустить две pending-записи для одной subscription. Не пиши код. Какие технические термины мне искать?

Так ChatGPT помогает тебе **построить словарь**, а не написать решение вместо тебя.

# Короткая шпаргалка

```text
1. Пишу задачу своими словами.

2. Спрашиваю:
   - с чем работаю?
   - что хочу сделать?
   - какое ограничение важно?
   - где это происходит?

3. Убираю слова, которые не влияют на смысл.

4. Оставляю 2–5 смысловых слов.

5. Делаю простой поиск.

6. Не жду, что первый запрос сразу даст ответ.

7. В результатах ищу новые технические термины.

8. Нашёл термин → ищу уже его.

9. Потом иду в документацию.

10. Не нашёл термин за 10–15 минут →
    спрашиваю ChatGPT только направление.
```

# Главная мысль

Не нужно думать:

> Как мне сразу догадаться, что нужно слово `unique`?

Правильнее:

```text
Я знаю:
"значение не должно повторяться"

↓

ищу:
django prevent duplicate field value

↓

по результатам узнаю новое слово:
unique

↓

дальше уже ищу:
django unique constraint
```

Со временем таких связей станет больше:

```text
"не повторяется"
→ unique

"всё или ничего"
→ atomic

"повтор безопасен"
→ idempotent

"слишком много запросов"
→ select_related / prefetch_related

"обновить относительно текущего значения"
→ F()
```

И именно из этих связей постепенно формируется технический словарь разработчика.

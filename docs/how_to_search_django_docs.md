# Как искать решение в документации, если знаешь только задачу

Главная проблема новичка обычно не в том, что он не умеет читать документацию, а в том, что он **ещё не знает название нужного инструмента**.

Ты думаешь:

> «Мне нужно запретить создавать две записи с одинаковым полем».

А документация использует другие слова:

- `unique`
- `constraint`
- `UniqueConstraint`
- `condition`

Поэтому правильный поиск обычно выглядит так:

```text
Задача своими словами
        ↓
Найти технический термин
        ↓
Найти этот термин в документации
        ↓
Разобраться в примере
        ↓
Применить к своей задаче
```

---

## Шаг 1. Сначала сформулируй задачу своими словами

Не пытайся сразу писать «правильный технический запрос».

Пиши так, как реально понимаешь задачу.

Например:

> Я хочу запретить создавать две записи, у которых одинаковое поле.

Или:

> Я хочу получить объект, а если его нет — создать.

Или:

> Я хочу получить связанные объекты одним запросом, чтобы Django не ходил в БД много раз.

Главное — сначала понять **что именно ты хочешь получить в результате**.

---

## Шаг 2. Раздели задачу на три части

Спроси себя:

```text
ГДЕ это происходит?
ЧТО я хочу сделать?
С ЧЕМ я это хочу сделать?
```

Например:

> Нельзя создать две записи с одинаковой `subscription`.

Получаем:

```text
Где?
Django ORM / Model / Database

Что?
Запретить дубликаты

С чем?
Поле subscription
```

Теперь у тебя появляются поисковые слова:

```text
django
model
duplicate
field
```

Этого уже достаточно для первой попытки поиска.

---

## Шаг 3. Не пиши длинный красивый вопрос

Например такой запрос:

```text
django orm forbid create two objects with equal field value
```

логичен для человека, но не очень удобен для поиска по документации.

Документация, скорее всего, не использует фразу:

```text
forbid create two objects
```

Она использует технические термины:

```text
unique
constraint
field
database
model
```

Поэтому лучше делать короткие запросы:

```text
django duplicate field
```

потом:

```text
django model unique field
```

потом:

```text
django unique constraint
```

Поиск — это не один идеальный запрос.

Это **цепочка уточнений**.

---

# Лестница поиска

Если ты вообще не знаешь название механизма, используй три уровня.

## Уровень 1. Поиск человеческими словами

Например задача:

> Запретить одинаковое значение поля.

Ищешь:

```text
django prevent duplicate field
```

или:

```text
django same field value multiple objects
```

Твоя цель на этом этапе — **не найти готовое решение**, а заметить технические слова.

Например ты видишь:

```text
unique
unique constraint
```

Отлично.

Теперь у тебя появилось название механизма.

---

## Уровень 2. Ищи найденный термин

Теперь запрос уже другой:

```text
django unique constraint
```

Вместо описания проблемы ты ищешь конкретный механизм.

---

## Уровень 3. Ограничь поиск официальной документацией

Можно использовать оператор Google:

```text
site:docs.djangoproject.com
```

Например:

```text
site:docs.djangoproject.com django unique constraint
```

или:

```text
site:docs.djangoproject.com django get_or_create
```

или:

```text
site:docs.djangoproject.com django transaction atomic
```

или:

```text
site:docs.djangoproject.com django select_related
```

Так Google будет искать только внутри официальной документации Django.

# Пример: как найти `UniqueConstraint`, если ты про него ничего не знаешь

Допустим твоя задача:

> Нельзя создать два `OutboxMessage` для одной `Subscription`.

Ты не знаешь ни про `UniqueConstraint`, ни про `condition`.

### Попытка 1

Ищешь:

```text
django prevent duplicate model field
```

В результатах замечаешь слово:

```text
unique
```

---

### Попытка 2

Ищешь:

```text
django model field unique
```

Находишь что-то вроде:

```python
unique=True
```

Теперь ты уже знаешь:

> Django умеет запрещать одинаковые значения.

Но потом замечаешь, что тебе нужно сложнее:

> Запрещать одинаковые `subscription` только когда `processed=False`.

---

### Попытка 3

Ищешь:

```text
django unique with condition
```

или:

```text
django unique constraint condition
```

Теперь появляются:

```text
UniqueConstraint
condition
```

---

### Попытка 4

Идёшь в документацию:

```text
site:docs.djangoproject.com UniqueConstraint condition
```

И уже читаешь конкретно про:

```python
UniqueConstraint(...)
```

Полный путь:

```text
"не хочу две одинаковые записи"
        ↓
django prevent duplicate model field
        ↓
unique
        ↓
django unique with condition
        ↓
UniqueConstraint(condition=...)
        ↓
официальная документация
```

# Можно ли сначала искать по-русски?

Да.

Если ты не знаешь английский термин, сначала можно искать по-русски.

Например:

```text
django сравнить два поля модели
```

В статье, Stack Overflow или форуме ты можешь встретить:

```text
F expression
F()
```

После этого уже переходишь к:

```text
site:docs.djangoproject.com django F expressions
```

То есть:

```text
Русский запрос
        ↓
нашёл технический термин
        ↓
проверил механизм в официальной документации
```

Статья, форум или чат в таком случае нужны не как окончательный источник истины, а как **указатель на название механизма**.

# Как читать документацию, когда ты её уже открыл

Не нужно читать огромную страницу сверху вниз.

Используй:

```text
Ctrl + F
```

и ищи конкретное слово:

```text
get_or_create
```

```text
select_related
```

```text
UniqueConstraint
```

```text
condition
```

---

## Читай в таком порядке

### 1. Что делает механизм?

Например:

> `get_or_create()` получает объект, а если его нет — создаёт.

### 2. Посмотри маленький пример

Не пытайся сразу понять все параметры.

### 3. Узнай, что метод возвращает

Например:

```python
object, created = Model.objects.get_or_create(...)
```

### 4. Посмотри важные ограничения

Например:

- работает ли это атомарно;
- нужны ли ограничения уникальности;
- какие бывают исключения.

### 5. Читай только параметры, которые нужны тебе

Не надо запоминать всю сигнатуру API.

# Не копируй пример сразу в свой проект

Если механизм новый, сначала представь маленький абстрактный пример.

Например:

```python
class User(models.Model):
    email = models.EmailField()
```

Задача:

> Нельзя иметь двух пользователей с одинаковым email.

Сначала разберись с этой простой задачей.

Потом возвращайся к своему:

```text
OutboxMessage
Subscription
processed=False
```

Так ты переносишь **идею**, а не копируешь код.

---

# Всегда проверяй: механизм действительно решает твою задачу?

Например ты нашёл:

```python
unique=True
```

Не останавливайся сразу.

Спроси:

> Какое именно правило эта конструкция гарантирует?

`unique=True` означает:

> Значение поля всегда должно быть уникальным.

А твоя задача:

> Значение должно быть уникальным только когда `processed=False`.

Значит `unique=True` не подходит.

Нужно продолжить поиск.

Это важная привычка:

```text
Нашёл похожий механизм
        ↓
сравнил его правило со своей задачей
        ↓
если не совпадает — продолжаю искать
```

# Когда спрашивать ChatGPT

Не нужно запрещать себе пользоваться ChatGPT.

Лучше изменить **тип вопросов**.

## Если 10–15 минут не можешь даже понять название механизма

Не спрашивай:

> Как мне написать это?

Лучше спроси:

> Мне нужно сделать X. Не пиши решение для моего проекта. Подскажи 1–3 механизма Django, которые мне стоит изучить.

Например:

> Мне нужно запретить несколько записей с одинаковой `subscription`, но только когда `processed=False`. Не пиши код. Скажи, что мне изучить.

Ответ может быть:

```text
Посмотри:
- UniqueConstraint
- condition у UniqueConstraint
- Q objects
```

После этого ты сам идёшь в документацию.

# Шпаргалка: полный алгоритм

```text
1. Что я хочу сделать человеческими словами?

2. Где это происходит?
   - Python
   - Django ORM
   - Models
   - HTTP
   - PostgreSQL
   - Tests
   - Templates
   - Forms

3. Выделяю 2–4 главных слова.

4. Делаю простой запрос:
   django + действие + объект

5. Ничего полезного?
   Укорачиваю запрос.
   Убираю длинное предложение.
   Оставляю главные понятия.

6. В результатах увидел незнакомый технический термин?
   Записываю его.

7. Ищу уже этот термин:
   django <термин>

8. Ограничиваю поиск документацией:
   site:docs.djangoproject.com <термин>

9. Открыл документацию:
   Ctrl + F → <термин>

10. Читаю:
    - что делает;
    - маленький пример;
    - что возвращает;
    - ограничения;
    - нужные мне параметры.

11. Пробую маленький пример.

12. Сам применяю к проекту.

13. Не понимаю концепцию?
    → спрашиваю ChatGPT "почему это работает так?"

14. Не знаю название инструмента после 10–15 минут?
    → спрашиваю ChatGPT только направление и термины.

15. Написал решение?
    → отдаю ChatGPT на ревью.
```

# Примеры поиска с позиции «я вообще не знаю название»

## 1. Получить объект или создать его

Задача:

> Получить объект, а если его нет — создать.

Первый запрос:

```text
django get object if exists otherwise create
```

Находишь:

```text
get_or_create()
```

После этого:

```text
site:docs.djangoproject.com django get_or_create
```

---

## 2. Безопасно увеличить значение поля на 1

Задача:

> Хочу увеличить число в БД на 1 и не потерять обновление, если два процесса работают одновременно.

Ищешь:

```text
django increment database field safely
```

или:

```text
django update field without race condition
```

Находишь:

```text
F expressions
```

Теперь:

```text
site:docs.djangoproject.com django F expression
```

---

## 3. Получить ForeignKey-объекты одним запросом

Задача:

> Я получаю `Subscription`, а потом обращаюсь к `product` и `user`, и Django делает много запросов.

Ищешь:

```text
django foreign key avoid multiple queries
```

или:

```text
django load related object one query
```

Находишь:

```text
select_related()
```

Теперь:

```text
site:docs.djangoproject.com django select_related
```

---

## 4. Откатить несколько операций с БД при ошибке

Задача:

> Если одна операция упала, предыдущие изменения тоже должны отмениться.

Ищешь:

```text
django rollback database changes if error
```

Находишь:

```text
transaction
atomic
```

Теперь:

```text
site:docs.djangoproject.com django transaction atomic
```

---

## 5. Проверить, есть ли хотя бы одна запись

Задача:

> Мне не нужно количество. Нужно просто узнать, есть ли запись.

Ищешь:

```text
django check queryset has any objects
```

Находишь:

```text
exists()
```

Теперь уже ищешь документацию по `QuerySet.exists()`.

# Как понять, куда идти: документация, Google или ChatGPT

```text
Я знаю название механизма,
но забыл синтаксис
→ официальная документация

Я знаю задачу,
но не знаю название механизма
→ Google / поиск по документации

Я нашёл механизм,
но не понимаю, почему он работает так
→ ChatGPT

Есть несколько вариантов,
не понимаю trade-offs
→ ChatGPT

Я написал своё решение
→ ChatGPT на ревью

Я вообще не понимаю,
как разложить задачу
→ ChatGPT за направлением,
  но не за готовым кодом
```

# Почему опытному разработчику искать проще

Потому что со временем формируется технический словарь.

Сначала ты думаешь:

```text
"не разрешить две одинаковые записи"
```

А опытный разработчик сразу переводит это в:

```text
uniqueness
constraint
UniqueConstraint
```

Или:

```text
"получить или создать"
→ get_or_create
```

```text
"связанные ForeignKey одним запросом"
→ select_related
```

```text
"изменить значение относительно текущего значения в БД"
→ F()
```

```text
"несколько изменений должны откатиться вместе"
→ transaction.atomic
```

То есть со временем ты не столько «лучше гуглишь», сколько быстрее понимаешь, **какие технические термины описывают твою проблему**.

# Полезно вести свой словарь инструментов

Можно завести файл:

```text
django_tools.md
```

И после каждой новой конструкции записывать:

```markdown
## UniqueConstraint

### Когда вспоминать

Когда нужно гарантировать уникальность данных на уровне БД.

### Как задача может звучать человеческими словами

- нельзя создавать дубликаты;
- не должно существовать двух одинаковых записей;
- это поле или набор полей должен быть уникальным.

### Что искать

django unique constraint
```

Не нужно превращать этот файл в копию документации.

Главное — сохранять связь:

```text
Как звучит проблема
        ↓
Как называется механизм
```

Именно эта связь со временем сильнее всего ускорит самостоятельный поиск.

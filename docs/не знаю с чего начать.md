# Что делать, если я не понимаю, с чего начать задачу

Главное правило:

> **Если я не понимаю, что писать в коде — сначала выясняю, как программа должна работать для пользователя.**

Не надо сразу придумывать классы, методы, списки, базы данных и архитектуру.

Сначала — поведение программы.  
Потом — код.

---

## 1. Покажи задачу на одном конкретном примере

Например, задача:

**«У пользователя может быть несколько счетов и несколько карт».**

Это слишком абстрактно.

Нужно представить конкретного пользователя:

```text
Иван Иванов

Счета:
1. Основной — 50 000 ₽
2. Накопительный — 12 000 ₽

Карты:
1. **** 1234
2. **** 5678
```

Теперь уже можно думать не про абстрактные «несколько счетов», а про конкретного Иванова.

---

## 2. Напиши сценарий работы программы без кода

Представь, что программа уже работает.

Напиши буквально по шагам, что делает пользователь и что отвечает программа.

Например:

```text
Вставляю карту.

Программа:
Введите PIN.

Я:
1234

Программа:
Выберите счёт:
1. Основной — 50 000 ₽
2. Накопительный — 12 000 ₽

Я:
1

Программа:
Выберите действие:
1. Снять деньги
2. Пополнить
3. Посмотреть баланс

Я:
1

Программа:
Введите сумму.

Я:
3000

Программа:
Выдано 3000 ₽.
Остаток: 47 000 ₽.
```

### Зачем это делать

Потому что из такого сценария становится видно:

- какие данные нужны;
- что должен выбирать пользователь;
- какие функции понадобятся;
- какие ситуации нужно обработать.

Если я **не могу даже написать такой сценарий**, значит я ещё не решила, как должна работать программа.

И код писать пока действительно рано.

---

# 3. Выпиши все вопросы, которые появились

Например:

```text
К чему относится PIN:
к пользователю или к карте?

Карта связана:
с одним счётом или с несколькими?

Если у пользователя один счёт:
показывать выбор счёта или сразу открывать его?

Можно ли иметь две карты, привязанные к одному счёту?

Можно ли переводить деньги между своими счетами?
```

Здесь не надо искать «идеально правильное банковское устройство».

Для учебного проекта достаточно принять решение:

```text
В моей программе будет так:
PIN принадлежит карте.

Одна карта привязана к одному счёту.

Несколько карт могут быть привязаны к одному счёту.
```

Главное — чтобы правила программы были понятны тебе самой.

---

# 4. Сделай данные руками

До красивой архитектуры.

Например:

```python
user_1 = {
    "name": "Иван",
    "accounts": [
        {
            "name": "Основной",
            "balance": 50000
        },
        {
            "name": "Накопительный",
            "balance": 12000
        }
    ]
}
```

Потом второй пользователь:

```python
user_2 = {
    "name": "Пётр",
    "accounts": [
        {
            "name": "Основной",
            "balance": 7000
        }
    ]
}
```

Пока неважно, красиво это или нет.

Цель:

> **увидеть реальные данные, с которыми должна работать программа.**

---

# 5. Возьми два разных примера

Не один.

Например:

### Иван

```text
2 счёта
1 карта
```

### Пётр

```text
1 счёт
2 карты
```

Почему именно два?

Потому что на одном примере сложно понять, что в программе постоянное, а что меняется.

На двух уже видно:

```text
у каждого пользователя есть счета

НО

количество счетов может быть разным
```

А значит где-то, скорее всего, понадобится список.

---

# 6. Напиши, что программа должна уметь прямо сейчас

Не весь проект целиком.

Например, первая версия:

```text
✓ показать счета пользователя

✓ выбрать счёт

✓ показать баланс выбранного счёта

✓ снять деньги

✓ не разрешить снять больше, чем есть

✓ обработать неправильный номер счёта
```

Это твоя текущая задача.

Не добавляем внезапно:

```text
— историю операций
— переводы другим людям
— блокировку карт
— SQLite
— лимиты
— валютные счета
```

Если пришла новая идея — записать в:

```text
ПОТОМ
```

и продолжать текущую задачу.

---

# 7. Напиши проверки

До написания основной логики.

Не обязательно полноценные автоматические тесты.

Просто:

```text
Запускаю программу
→ вижу счета Иванова

Выбираю счёт 1
→ вижу баланс 50 000

Снимаю 3000
→ баланс становится 47 000

Пытаюсь снять 100 000
→ программа отказывает
→ баланс остаётся 47 000

Ввожу счёт 15
→ программа сообщает об ошибке
→ предлагает выбрать ещё раз
```

Теперь понятно, **что значит «задача готова»**.

---

# 8. Делай проект маленькими рабочими стадиями

Не надо сразу реализовывать:

```text
Пользователь
→ несколько счетов
→ несколько карт
→ переводы
→ SQLite
```

Это слишком большой кусок.

Разделяем.

## Стадия 1

У пользователя появляется понятие **счёта**.

Но счёт пока только один.

Например:

```text
User
 └── Account
      └── balance
```

Программа должна работать почти так же, как раньше.

---

## Стадия 2

Добавляем несколько счетов.

```text
User
 ├── Account
 ├── Account
 └── Account
```

Появляется:

```text
Показать счета
Выбрать счёт
Работать с выбранным счётом
```

---

## Стадия 3

Добавляем карты.

```text
User
 ├── Account
 │    └── Card
 │
 └── Account
      ├── Card
      └── Card
```

---

## Стадия 4

Добавляем переводы:

```text
счёт → счёт

счёт → карта

карта → карта
```

---

## Стадия 5

Когда логика уже работает — подключаем SQLite.

То есть база данных появляется **не для того, чтобы разобраться в логике программы**.

Она появляется тогда, когда мы уже понимаем:

```text
какие данные существуют

как они связаны

что программа с ними делает
```

---

# 9. После каждого этапа программа должна работать

Это очень важное правило.

Плохо:

```text
Я сейчас перепишу половину программы,
потом сделаю счета,
потом карты,
потом переводы,
и когда-нибудь всё снова заработает.
```

Хорошо:

```text
Этап 1 сделал
→ программа работает.

Этап 2 сделал
→ программа работает.

Этап 3 сделал
→ программа работает.
```

Если после каждого небольшого изменения программу можно запустить и проверить, намного сложнее окончательно запутаться.

---

# Что делать, если я опять зависла

## Вариант 1. Нарисовать данные

Прямо схемой:

```text
USER
│
├── ACCOUNT
│   ├── balance
│   └── CARD
│
└── ACCOUNT
    ├── balance
    ├── CARD
    └── CARD
```

Не держать всё в голове.

---

## Вариант 2. Взять один конкретный случай

Если непонятно:

> «Как реализовать несколько счетов?»

Не реализовывать пока «несколько».

Сделать:

```text
Иван
→ Основной счёт
→ 50 000 ₽
```

Потом:

```text
Иван
→ Основной счёт
→ Накопительный счёт
```

---

## Вариант 3. Написать, как хотелось бы пользоваться кодом

Например, я хочу в итоге писать:

```python
user.show_accounts()
```

или:

```python
account.withdraw(3000)
```

Сначала можно написать желаемый вызов.

А потом уже решить:

> Что должно существовать, чтобы эта строка заработала?

Например:

```python
account.withdraw(3000)
```

значит:

```text
нужен Account

у него должен быть balance

нужен метод withdraw()

метод должен получить сумму

метод должен проверить баланс

метод должен изменить balance
```

Одна строчка сама раскладывает задачу.

# Мой алгоритм, когда «я вообще не понимаю, что делать»

```text
1. НЕ ПИСАТЬ КОД СРАЗУ.

2. Взять одного конкретного пользователя.

3. Написать сценарий:
   что нажимает пользователь
   →
   что отвечает программа.

4. Выписать вопросы, которые появились.

5. Самой принять правила для своего проекта.

6. Сделать 2 конкретных примера данных руками.

7. Написать список:
   «программа должна уметь...»

8. Написать проверки:
   «делаю X → получаю Y».

9. Выбрать ОДНУ маленькую часть.

10. Реализовать её.

11. Запустить программу.

12. Только когда она работает —
    переходить к следующей части.
```

---

# Самое главное

Когда появляется мысль:

> «Как мне вообще правильно реализовать пользователей, счета и карты?»

вопрос пока слишком большой.

Нужно заменить его на маленький:

> «Как сделать, чтобы у Иванова было два счёта и я могла вывести их в консоль?»

Сделала.

Следующий:

> «Как выбрать один из этих счетов?»

Сделала.

Следующий:

> «Как снять деньги именно с выбранного счёта?»

Сделала.

И только потом:

> «Как это нормально оформить через классы?»

---

## Формула

**Конкретный пример → сценарий → вопросы → данные → проверки → маленький код → запуск → следующий шаг.**

Не:

**архитектура → классы → куча кода → надеяться, что всё заработает.**
